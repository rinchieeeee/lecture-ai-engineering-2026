### 基礎(LoRAのハイパーパラメータ変更比較)

自前マシンの NVIDIA GeForce RTX 3090 を GPU 環境として使用し、LoRA の rank を baseline の 16 から 4 に下げて比較した。
`lora_alpha` は両方とも 32 に固定した。モデルは `Qwen/Qwen3.5-0.8B`、学習率は `2e-4`、学習量は 20 エポック（40 ステップ）、seed は 42 とし、データとその他の学習・評価条件も揃えた。

| 指標 | baseline（rank 16） | rank 4 |
|---|---:|---:|
| 学習後の `format_rate`| 100%（21/21） | 100%（21/21） |
| 学習後の `content_rate`| 90.48%（19/21） | 90.48%（19/21） |
| 最終ログの loss | 0.01387327 | 0.01291749 |
| 学習時間 | 41.2 秒 | 39.7 秒 |

最終 loss は、40 ステップ目に記録された最後の 10 ステップ区間の平均であり、全学習の平均 loss とは異なる。学習時間は `trainer.train()` の実行時間で、モデルの読み込みと学習前後の評価は含まない。

rank を 4 分の 1 にしても、今回の評価では format_rate・content_rate は変わらず、21 問の回答原文も baseline と一致した。最終 loss は約 6.9% 低下し、学習時間は 1.5 秒短くなったが、各条件 1 回の測定なので一般的な優劣は断定できない。また、alpha を固定したため、更新倍率の `alpha/r` は 2 から 8 に変化している。

### 実践(FAQデータを自分で用意し、学習前後の結果を見比べる)

題材は自分のプロフィールとし、出身地、専攻、興味のある分野、結婚の有無と時期、今後やってみたいことの5項目を FAQ にした。各項目について言い換え質問を用意し、FAQに書かれた事実を尋ねるものを GROUNDED とした。学習データは14件、検証データは7件、テストデータは21件で、難しい質問を追加した後のテストは31件になった。

#### 学習前後の精度比較
| 指標 | 学習前 | 学習後 |
|---|---:|---:|
| `format_rate` | 64.52%（20/31） | 100%（31/31） |
| `content_rate` | 9.68%（3/31） | 90.32%（28/31） |
| 両方合格 | 9.68%（3/31） | 90.32%（28/31） |

根拠なしの質問は、FAQの話題に関連していても、FAQ本文に答えがない情報を尋ねるように作った。たとえば「出身地から現在の居住地を推測できるか」「結婚した月はいつか」「Semantic IDs を実装する製品や時期は何か」といった質問である。さらに、将来の目標を現在の実績と取り違えないかを見るため、「Semantic IDs はすでに社内プロダクトに導入されていますか」も加えた。これらには答えを補完・推測せず、`needs_review: true` で確認を促すことを期待した。

学習後に残った不合格は3問で、いずれも根拠なしの質問だった。「現在取り組んでいる研究の進捗」「2024年の何月に結婚したか」「Semantic IDs をどの機能にいつ実装するか」に対して、関連する FAQ の記述を答えてしまい、`needs_review: false` とした。FAQから分かる事実と、質問が求める未記載の詳細を切り分けられなかった。

退行した質問(学習前は正解だが学習後不正解となる質問)は「現在取り組んでいる研究の進捗を教えてください」で、学習前は合格したが、学習後は今後の目標を進捗として断定し不合格になった。知識質問では、現住所と Semantic IDs の研究開始時期について、学習前は推測で断定したが、学習後は確認を促す回答に変わった。結婚相手の名前は前後とも確認を促し、出身地は前後とも京都府と答えた。

### 発展

#### 学習前後の精度比較

`scripts/make_sft_dataset.py` を使い、講座の用語集58語から `messages` 形式の Q&A データを作成した。学習用は182件（掲載語の定義174件、未掲載語への確認要求8件）、検証用は62件とした。評価用には、掲載語を直接尋ねる質問、同じ語を説明や利用場面から尋ねる言い換え質問、未掲載語の質問を各12問、合計36問用意した。学習・検証・評価で質問文を重複させず、未掲載語は語自体も分けた。

RTX 3090 上で `Qwen/Qwen3.5-0.8B` を LoRA（rank 16、alpha 32、学習率 `2e-4`、20エポック・460ステップ、seed 42）で学習した。学習時間は約383秒（6.4分）だった。学習前後で同じ36問、同じ system 指示、同じ生成条件（貪欲生成、最大384トークン、思考モード無効、終了トークン固定）を使い、入力には用語集本文を渡さなかった。

| 指標 | 学習前 | 学習後 |
|---|---:|---:|
| `format_rate` | 30.56%（11/36） | 100%（36/36） |
| `content_rate` | 0%（0/36） | 44.44%（16/36） |
| 両方合格 | 0%（0/36） | 44.44%（16/36） |

`format_rate` は JSON のキーと型が指定どおりか、`content_rate` は `needs_review` が正解と一致し、回答に必須語句が全て含まれるかで判定した。以下の「正解」は形式と内容の両方に合格したものとする。未掲載語は一般に実在していても、「用語集には記載がなく、確認が必要」と答え、`needs_review: true` にするのが正解である。

| 質問の種類 | 学習前の正解 | 学習後の正解 |
|---|---:|---:|
| 掲載語を直接尋ねる質問 | 0/12 | 12/12 |
| 言い換えた質問 | 0/12 | 1/12 |
| 未掲載語の質問 | 0/12 | 3/12 |

| 学習前後の変化 | 件数 |
|---|---:|
| 学習後に正解できるようになった問題 | 16 |
| 学習後に不正解になった問題（退行） | 0 |
| 学習前後でともに正解だった問題 | 0 |
| 学習前後でともに不正解だった問題 | 20 |

学習後は、用語名を直接指定した質問には12問全てで正解し、JSON形式も全36問で守れるようになった。一方、言い換えでは構造化出力の質問だけが正解だった。たとえば LoRA の名前を直接尋ねると定義を答えられたが、「元の重みを固定し、更新分を小さい二つの行列の積で表して学ぶ方法」と尋ねると「用語集には記載がない」と回答した。学習済みの定義に対応する説明でも、用語名が明示されないと結び付けられないケースが残った。

未掲載語では、Transformer、自己注意機構、ビームサーチには確認を求められたが、残り9問は不正解だった。RLHF については、用語集にないにもかかわらず重みの更新に関する説明を生成し、`needs_review: false` とした。今回の結果では、定義の再現と出力形式の改善に比べ、言い換えへの対応や用語集の収録範囲の判断には課題が残った。

採点は必須語句による簡易自動採点のため、意味が近くても表現が異なると不合格になる場合がある。学習前の4回答は生成上限に達しており、回答が途中で切れた可能性もある。掲載語の定義自体は全て学習データに含まれ、今回比較したのは未知の質問文への対応である。固定36問・seed一つの結果として扱う。
