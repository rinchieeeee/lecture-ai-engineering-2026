- 検索だけを実行して見つかったページと、その本文で確認できたこと：
  - `python -m app.retrieval "LoRA QLoRA 違い"` の上位5件はすべて第2回(`lec02-main`)から取得された：1位 p.52(LoRA と QLoRA)、2位 p.51(PEFT)、3位 p.60(今日の演習：QLoRA)、4位 p.47(根拠と諸説：RAGとFT)、5位 p.61(演習の進め方)。
  - 1位の p.52 に「元の重みは固定し、小さな『差分』だけを学習する(LoRA)。さらに元の重みを 4bit に圧縮する(QLoRA)」と直接の根拠があり、2位の p.51 の比較表も裏付けになっていた。3〜5位は関連語を含むが直接の根拠ではないページだった。
- `--trace`で見えたツール呼び出し(ツール名・引数・回数、Treeでたどった目次など)：
  - 全文投入：ツール呼び出しなし(1回のリクエストで全資料227,971文字を一括投入)。
  - ベクトル検索：`search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'})` × 1回。
  - Tree：`browse_tree` × 4回。`{}`(講義一覧) → `lec02-main`(第2回 基盤モデルの仕組み) → `lec02-main-s045`(選んだモデルを、いつ・どう直すか) → `lec02-main-p052`(p.52 の全文717文字を取得)と最短経路で到達。

  - どの方式も根拠ページ(p.52、または p.51〜52)自体は正しく取得できており、情報の不足は起きなかった。
  - 全文投入では該当ページを特定できていたにもかかわらず、システムプロンプトの「宿題の答えそのものは書かず、考え方のヒントで導く」というルールを過剰に適用し、直接の回答を避けてヒント形式にとどまった。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  - 採用したい方式：ベクトル検索
  - 理由：
    - 今回の質問では1〜2ページ(p.51〜52)で根拠が完結しており、ベクトル検索が最も少ないトークン数(入力 3,178 tokens)・最安コスト($0.001436、全文投入の約1/25)で正確な回答と引用を出せたため。
    - Tree は埋め込みDB不要で説明可能性が高い一方、往復回数が増えて累積トークン・APIエラー遭遇リスクが上がりやすい。
    - Graph は前後ページや共通用語をたどれるため複数箇所にまたがる質問に強いが、単一ページで完結する質問では入力トークンと処理時間がやや過剰になった。
  - 比較条件の限界：
    - 全文投入は全9資料・438ページを対象としているのに対し、他3方式は第1〜3回の本講義3資料・214ページのみを対象としており、条件が完全に同一ではない。また各方式1回ずつの実行結果(単一質問)であり、APIの混雑状況や生成の揺らぎの影響を受ける。
- 気づき・疑問：
  - 全文投入は検索漏れがない反面、入力トークン・コストが数十倍に膨らみ、情報量が多いせいか指示文の解釈(ヒント形式にするか直接答えるか)にも他方式との違いが出た。
  - 質問に「第2回の説明では」と明示されていたため Tree は迷わず p.52 にたどり着けたが、どの回・章にあるか分からない質問では Tree の探索回数が増えたり見落としたりする可能性があり、質問の性質によって有利な方式が大きく変わりそうだと感じた。
